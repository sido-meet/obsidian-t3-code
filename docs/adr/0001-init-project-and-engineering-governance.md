# ADR-0001: 工程初始化与严谨治理规范建立

## 状态
**Accepted**

## 日期
2026-11-18

## 背景与上下文
T3-Codian 是一个连接 Obsidian 本地知识库与 T3 Code AI Agent 体系的复杂集成项目。涉及客户端协议交互、本地文件读写、用户隐私与自动化智能体研发。
若缺乏强有力的工程管理与 Agent 行为边界约束，容易引发以下严重风险：
1. Agent 随意在主分支提交未经验证的代码，破坏代码库稳定性；
2. 缺乏 TDD 与自动化验证，导致深层回归缺陷难以定位；
3. 未加限制的 Agent 行为可能修改甚至破坏用户的正式 Obsidian Vault 笔记；
4. 密钥泄露与无序发布风险。

## 决策内容
1. **建立不可动摇的 15 条 Agent 行为铁律**，将其固化在项目根目录 `AGENTS.md`，所有接入 Agent 均须无条件遵守。
2. **推行严格的 Trunk-Based + Feature Branch 开发流**：禁止在 `main` 直接开发，禁止 force push，合并权限收归用户独占。
3. **全面接入 Superpowers 软件工程技能体系**：在规划、设计、TDD、审查、分支收尾等阶段全面贯彻自动化规约。
4. **四件套文档化管理**：将需求 (`docs/PRD.md`)、架构 (`docs/ARCHITECTURE.md`)、当前状态 (`docs/STATUS.md`)、工作流 (`docs/WORKFLOW.md`) 独立分权管理，杜绝编造虚假记录。
5. **Obsidian 安全沙箱隔离**：测试开发必须隔离于用户真实 Vault 之外，任何笔记修改必须经过 Diff 确认。

## 影响与推论
- **正面收益**：
  - 代码质量与安全水位得到工程级保障；
  - 研发过程高度结构化、透明、可复现；
  - 彻底规避用户正式笔记与机密泄露风险。
- **负面成本/妥协**：
  - 初期建立各阶段流程与测试的准备工作较多，单次功能合入需严格经历完整链路，但长期维护与交付成本大幅降低。
