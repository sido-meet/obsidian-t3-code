## 1. 背景与问题定义

### 1.1 背景
Obsidian 作为以本地优先（Local-First）、Markdown 语法和双向链表为核心的顶级个人知识管理系统（PKM），拥有极其庞大的专业知识工作者、学者和开发者群体。然而，目前 Obsidian 生态中的绝大部分 AI 插件仍停留在传统的“单轮/多轮补全聊天”或“基础文本重写”阶段，缺乏真正具备**自主规划、工具调用、文件环境感知、多智能体协同（Swarm）以及工程级测试与验证**的 Agentic AI 能力。

与此同时，**T3 Code** 已经构建了领先的 Agent Client Protocol (ACP) 与 MCP 编排架构，支持深度的代码操作、子 Agent 派发、Git Worktree 隔离和多模型调度。

### 1.2 目标定位
**T3-Codian** 旨在打破 Obsidian 与 T3 Code 之间的壁垒，将 T3 Code 工业级的 AI Agent 能力引入 Obsidian 笔记工作流，打造新一代“自主智能研究与知识助理”。

---

## 2. 目标用户与核心使用场景

| 用户角色 | 核心痛点 | T3-Codian 解决方案 |
| :--- | :--- | :--- |
| **知识创作者 / 作家** | 写作缺乏结构灵感，收集的海量碎片笔记难以自动梳理出逻辑大纲。 | 唤醒 Brainstorming Agent，自主读取当前双链网络，提出结构化洞见与章节提纲。 |
| **科研学者 / 学生** | 文献整理耗时，无法快速对关联论文笔记进行交叉对比与逻辑验证。 | 启动文献分析子 Agent，跨笔记提取论点，并在侧边栏提供可复核的引文溯源与 Diff 预览。 |
| **独立软件开发者** | 在 Obsidian 中记下需求与设计，但需频繁在 IDE 与笔记间切换以验证代码。 | 在笔记中直接唤起 T3 Code 智能体执行代码片断测试、运行脚本或调用 MCP 工具并回传结果。 |

## 3. 核心功能规划与阶段路线图

### 阶段 0：工程管理与基础设施（当前阶段）
- [x] 完成 P0 环境核查（Git, Node.js, npm, gh, Superpowers）。
- [x] 确立项目代码库、管理规范（`AGENTS.md`, `WORKFLOW.md`, `STATUS.md`）。
- [x] 初始化本地 Git 仓库，建立 `main` 分支防护与 ADR 架构决策机制。

### 阶段 1：需求细化与通信协议设计（下一步规划）
- [ ] 制定 Obsidian Plugin 与 T3 Code ACP (Agent Client Protocol) 的通信协议规范。
- [ ] 架构方案评审与关键 ADR 决策（通信方式：Localhost WebSocket / IPC Pipe / CLI stdio）。
- [ ] 定义数据传输格式（提示词注入、流式 Token、工具调用请求与用户确认交互卡片）。

### 阶段 2：Obsidian 交互视图与 UI 原型开发
- [ ] 创建遵循 Obsidian 设计语言的侧边栏视图（ItemView / Chat View）。
- [ ] 实时流式响应与 Markdown 渲染支持（代码高亮、Mermaid 图表、折叠引用）。
- [ ] Agent 思考链路（Thought chain）与工具执行状态的可视化展示。

### 阶段 3：Vault 适配器与安全防护系统
- [ ] **只读探索模式**：Agent 可读取活动笔记、引用笔记或选中文本。
- [ ] **安全修改机制**：对 Vault 文件的写入必须先生成 Diff 预览，严禁直接未经确认覆写用户笔记。
- [ ] **沙箱隔离**：测试与开发执行严格限定在虚拟目录或测试库中，保护用户真实知识库资产。

### 阶段 4：集成测试、打包与发布
- [ ] 端到端集成测试（E2E）覆盖关键交互路径。
- [ ] 满足 Obsidian Community Plugins 发布审核标准。
- [ ] 用户使用手册与视频展示制作。

## 4. 非功能性需求 (NFR)

1. **安全性（最高优先级）**：
   - 严禁任何未经用户明示授权的破坏性文件写入。
   - 敏感信息（Token、用户笔记个人隐私）不得外泄至未加密通道或非授权云端。
2. **性能与响应延迟**：
   - 插件加载时间小于 100ms，不得阻塞 Obsidian 主渲染线程。
   - 消息流式接收首字延迟（TTFT）控制在网络物理极限内。
3. **跨平台兼容性**：
   - 完美适配 Windows 10/11、macOS (Intel/Apple Silicon) 与主流 Linux 发行版。
4. **可靠性与断线重连**：
   - 当 T3 Code 后台服务或进程重启时，前端应具备优雅的重连提示与状态恢复机制。
